# 《琵琶曲》Web Demo

《琵琶曲》是一款 2D 横版弹幕 Boss 战 Demo。玩家直接控制角色的屁股躲避弹幕，在短暂窗口内反弹特殊弹积攒能量，并在短期强化与满能量大招之间作出选择。

当前版本：`1.0.0-rc.1`（Demo 发布候选版）

当前开发阶段：Demo D8（完整五阶段集成、回归与发布）。正式入口默认运行完整 Demo；历史原型仍保留在显式兼容路由中。

## 在线试玩

[打开 GitHub Pages 试玩版](https://yylee-orange.github.io/SongOfPipa.github.io/)

建议使用桌面版 Chrome 或 Edge，并保持浏览器标签页处于前台。游戏以 1280 × 720 为逻辑分辨率，会根据窗口尺寸等比缩放。

## 操作方式

- `WASD`／方向键：移动屁股，也就是唯一受击核心。
- `Z`／`J`：开启短暂反弹窗口；成功反弹特殊弹可获得 1 点能量。
- `X`／`K` 短按：消耗 2 点能量，进入 3.5 秒强化，期间接触核心的弹丸会自动反弹。
- 满 10 点能量时长按 `X`／`K` 2 秒：释放大招，吸收场上弹幕并从屁股处连续射出等量反击弹；每颗反击弹命中时独立伤害 Boss，演出期间无敌。
- 胜利或失败后按 `Enter`：重新开始。

普通弹在常态下只能躲避。特殊弹具有不同的颜色、轮廓和脉冲效果，需要在靠近屁股时主动反弹。反弹后的弹丸按照接触位置决定出射方向，只会在屏幕上下边界镜面弹射，到达左右边界后飞出。

## 当前 Demo 内容

- 三锚点程序骨骼与正式角色贴图：头部有限游移、梯形躯干跟随、固定脚底与弹性腿部连接。
- 屁股覆盖左侧至中央活动区域，是控制点、受击点与反弹反馈点。
- 3 点生命、受伤无敌、胜负结算与快速重开。
- 五阶段 Boss：左轮教程、AK47 连射、霰弹枪／追踪火箭、三类召唤物，以及横向／扫射激光与弹药桶反制。
- 四次换阶段夺械与一次最终夺械；玩家拾取 Boss 武器完成压制后继续下一阶段或进入胜利。
- 0～10 点能量、2 点强化与 10 点大招的完整战斗循环。
- 大招吸收、连射、Boss 命中反馈及安全退场。
- 单层横向无限滚动室内背景，以及 Boss、玩家、弹丸、火箭、激光、弹药桶与召唤物正式贴图。

## 本地开发

环境要求：Node.js 22（建议使用当前 LTS 版本）与 npm。

```bash
npm ci
npm run dev
```

默认开发地址：<http://127.0.0.1:5173/>，直接进入完整 Demo 正式流程。

Demo 正式流程也可显式使用 <http://127.0.0.1:5173/?demo=1>。五个 Boss 阶段共用同一个战斗场景并在场景内顺序转场；`1774×887` 背景按逻辑高度等比显示为 `1440×720`，以真实显示宽度和 `100 px/s` 速度持续向左循环，不会被横向压缩到画布宽度。

开发调试入口：<http://127.0.0.1:5173/?demoDebug=1>。阶段 1～5 已依次接入左轮逐发、AK47 间歇连射、霰弹枪／追踪火箭、三类召唤物，以及横向／扫射激光与特殊弹弹药桶；五个阶段均复用普通／特殊弹、反弹、能量、强化和大招的实际战斗循环。五个阶段生命归零后均进入真实夺械：前四次分别使用左轮、AK47、实际持有的重武器与召唤器完成压制并进入下一阶段，第五次拾取激光枪，蓄力后持续照射约 5 秒并进入最终胜利。第三阶段可用 `G` 在霰弹枪／火箭发射器间切换；第四阶段拾取召唤器后只会生成锁定 Boss 的玩家方苦力怕。覆盖层中可用数字键 `1`～`5` 直达阶段，`R` 复位、`T` 启动当前阶段真实夺械，`F` 触发武器后坐，`M`／`P`／`C` 在第四阶段强制生成对应敌方召唤物；第五阶段可用 `B`／`U` 强制普攻／大招、`Y` 切换扫射起点、`Q` 循环连续普攻计数，以及 `N`／`V`／`I`／`O` 生成／充满／立即引爆／哑火弹药桶。点击“Boss受伤”会一次清空当前阶段生命并触发真实转场，键盘 `H` 仍每次对头部结算 1 点调试伤害。也可用 `?demoPhase=1`～`?demoPhase=5` 选择初始阶段。Boss 数值直接在集中配置文件中修改，不提供网页数值编辑器。

历史原型兼容入口：<http://127.0.0.1:5173/?prototype=1>。

## 测试与构建

```bash
npm test
npm run typecheck
npm run test:rig
npm run test:movement
npm run test:combat
npm run test:demo
npm run build
npm run preview
```

生产构建输出到 `dist/`。每次推送到 `main` 分支后，GitHub Actions 会重新执行类型检查、骨架／移动／战斗／完整 Demo 自动化测试和生产构建，并将构建结果部署到 GitHub Pages。

## 项目结构

```text
src/
  game/
    entities/    玩家骨骼、Boss 与弹丸实体
    demo/        五阶段 Boss、转场、背景、资源与专项实体
    scenes/      启动、完整 Demo 与历史原型场景
    systems/     战斗、碰撞与技能逻辑
    ui/          HUD
tests/           骨骼、移动与战斗自动化测试
public/assets/   后续正式资源入口
```

当前开发已进入 Demo 阶段。后续批次目录与执行规范见 [DEMO_PLAN.md](./DEMO_PLAN.md)；原型玩法规则和验收记录保留在 [DEVELOPMENT_PLAN.md](./DEVELOPMENT_PLAN.md)。

## 自动部署

部署流程位于 `.github/workflows/deploy-pages.yml`：

1. 检出 `main` 分支代码并安装锁定依赖。
2. 执行类型检查和全部自动化测试。
3. 生成 Vite 静态构建。
4. 将 `dist/` 发布到 GitHub Pages。

如仓库首次启用 Pages，请在 GitHub 仓库的 **Settings → Pages → Build and deployment** 中将 Source 设为 **GitHub Actions**。工作流首次成功完成后，上方在线试玩链接即可访问。
