# 模块 07：Demo 集成验收与发布

状态：D8 本地发布候选已封存，等待同步与 Pages 验证
对应批次：D8

## 模块目标

把已分别验收的优化项、五阶段 Boss、四次换阶段夺械、一次最终夺械、单层滚动背景和双方骨架美术合并为可完整游玩的 Demo 发布候选。

## 集成范围

- 从开局到第五阶段最终夺械完成并胜利，或玩家失败的完整流程。
- 正式模式与同场景调试覆盖层的隔离。
- 五阶段机制、转场、背景与双方美术的组合回归。
- 性能、分辨率、浏览器、失焦恢复和重新开始验证。
- 生产构建与 GitHub Pages 线上版本验证。

## RC1 发布口径

- 版本：`1.0.0-rc.1`，根地址默认进入完整 Demo；已验收历史原型保留在 `/?prototype=1`。
- 完整流程：阶段 1～5 顺序战斗，四次换阶段夺械，第五阶段最终夺械后胜利；玩家失败或胜利后按 `Enter` 重开。
- 调试入口：`/?demoDebug=1` 和 `/?demoPhase=1～5`，只增加覆盖层与初始阶段选择，不建立第二套玩法场景。
- 目标环境：桌面版当前稳定 Chrome 与 Edge；逻辑分辨率固定 `1280×720`，页面使用等比 FIT 适配窗口。移动端、Safari 与 Firefox 不作为 RC1 阻断矩阵。
- 性能口径：支持环境中以 60 FPS 为目标；调试覆盖层显示实时 FPS 和显示尺寸。自动化继续覆盖 300 枚弹丸级别的逻辑压力，实际视觉性能以本地和 Pages 烟雾测试为准。
- 音频、完整手柄体验、外部试玩统计和额外可访问性增强不纳入 RC1 阻断范围；不得在没有真实数据时伪造试玩结论。
- 发布目标：原 GitHub 仓库 `YYlee-orange/SongOfPipa.github.io` 的 `main` 分支，由 GitHub Actions 构建并发布 Pages。

## 发布步骤

1. 执行 `npm test`、`npm run typecheck`、`npm run build` 与 `git diff --check`。
2. 在根地址检查正式模式无调试控件，在 `?demoDebug=1` 检查覆盖层，在五个 `?demoPhase=N` 页面检查阶段资源与运行状态。
3. 提交完整 Demo 继承工作区并推送 `main` 到原 `origin`。（本地验证已完成，待同步。）
4. 等待 GitHub Actions 完成，检查 Pages 根地址加载 RC1；若远端发布状态不可读取，则明确报告本地推送成功但线上状态待确认。
